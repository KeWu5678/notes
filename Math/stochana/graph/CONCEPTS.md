# Part 1 — the schema

## Node labels

| label | definition | examples |
| --- | --- | --- |
| `:Object` | A thing that exists in the theory. | Brownian motion, a filtration, M, L(M), the predictable σ-field |
| `:Property` | An arity-1 predicate: something a single object can satisfy. | adapted, continuous, L²-bounded, progressively measurable |
| `:Relation` | An arity-≥2 predicate: something that holds between objects. A property is just a relation of arity 1, so the two differ only by arity. | modification, indistinguishable, subset of, dense in |
| `:Statement` | An assertion made by the notes, carrying its verbatim text, page and provenance. This is the unit that gets cited. | Proposition 1.1.4, Theorem 3.3.6, Exercise 1 |
| `:Definition` | A statement that *introduces* a concept rather than asserting something about existing ones. Always carries `:Statement` as well — Neo4j labels are flat, so nothing is inherited automatically. | Definition 1.1.1 |
| `:Fact` | A reified assertion — a predicate applied to named arguments. Created **only** when something must point at the assertion itself, as when one statement declares two facts equivalent. Everywhere else an assertion is an edge, because an unbound fact is isomorphic to its predicate and a node would be pure indirection. | "M has a right-continuous modification" in Theorem 1.3.12 |
| `:Source` | A location in the notes: chapter and section. Provenance, not mathematics. | §1.1 |

## Layer 1 — statement edges

Extracted from the notes. Exact, provenance-bearing, and the justification for everything in layer 2.

| edge | from → to | definition | keys |
| --- | --- | --- | --- |
| `CITES` | Statement → Statement | This statement's text or proof references that one. Read mechanically from the PDF's link annotations, so it is ground truth. | _via is not needed — the edge itself is the citation |
| `REQUIRES` | Statement → Property \| Relation | This statement assumes that predicate. Unbound: it records *that* left-continuity is assumed, not of which object. |  |
| `CONCLUDES` | Statement → Property \| Relation | This statement asserts that predicate. | negated |
| `DEFINES` | Definition → Object \| Property \| Relation | This definition introduces that concept. The concept layer's provenance. |  |
| `ABOUT` | Statement → Object | The objects the statement is about — its subject. |  |
| `IN` | Statement → Source | Where the statement sits in the notes. |  |
| `PREDICATE` | Fact → Property \| Relation | The predicate a reified assertion applies. |  |
| `ARG` | Fact → Object | An argument of a reified assertion; `i` is its position. | i |

## Layer 2 — concept edges

Derived by projection from layer 1, never authored by hand. This is the layer you browse: one hop from an object to its neighbours.

| edge | from → to | definition | keys |
| --- | --- | --- | --- |
| `SUFF` | Property \| Relation → Property \| Relation | The source predicate is sufficient, **on its own**, for the target. Emitted only when the statement has exactly one hypothesis, so the edge is true read in isolation. | _via |
| `SUFF_GIVEN` | Property \| Relation → Property \| Relation | The source predicate is sufficient for the target **only together with** the conditions in `under`. Never confuse with the bare form: alone, the source does not suffice. | _via, under |
| `NOT_SUFF` | Property \| Relation → Property \| Relation | The source is **not** sufficient for the target — the converse fails in general. First-class, because a graph that cannot say this lets an agent derive the converse. | _via |
| `NOT_SUFF_GIVEN` | Property \| Relation → Property \| Relation | Not sufficient even together with `under`. | _via, under |
| `HAS_PROPERTY` | Object → Property | A named object satisfies a property. | _via, under |
| `NOT_HAS_PROPERTY` | Object → Property | A named object does not satisfy a property. | _via, under |
| `EQUIVALENT` | Fact → Fact | The two assertions hold under exactly the same circumstances — each is sufficient for the other. The reason `:Fact` exists: an equivalence needs assertions as endpoints, and an edge cannot end on an edge. | _via, under |
| «relation name» | Object → Object | One edge type per `:Relation` node, named after it — `SUBSET_OF`, `DENSE_IN`, `EQUALS`, `HAS`, and their `NOT_` forms. Generated when a statement concludes a binary relation between two *named* objects. None exist yet: the space inclusions live in chapter 4. | _via, under |

## Edge keys

`_`-prefixed keys are bookkeeping; everything else is mathematics.

| key | meaning |
| --- | --- |
| `_via` | Bookkeeping. The node id of the statement that justifies this edge — every derived edge can be traced back to a citable page. |
| `under` | Mathematics. The further hypotheses this edge depends on, as concept ids (never prose). A denormalization for browsing; the exact form is the statement's REQUIRES edges. |
| `negated` | Mathematics. Marks a CONCLUDES edge whose assertion is a denial. |
