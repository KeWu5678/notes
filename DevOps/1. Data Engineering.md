### In-memory Database (OLTP; Redis)
the online database: very low-latency, very high cocurrency. 

### Data Warehouse (OLAP; redshift)
Indexed/Optimized data: low-latency, high cocurrency. 

### Data Lake (blob storage: Athena/S3 bucket) 
Anything else. 

|             | Redis                 | S3                     | Redshift             | Athena          |
| ----------- | --------------------- | ---------------------- | -------------------- | --------------- |
| Storage     | RAM (+ optional disk) | Object storage (disk)  | Disk (columnar)      | Reads S3        |
| Latency     | µs (microseconds)     | 10–100 ms per object   | ms–sec               | sec–min         |
| Capacity    | GB–TB (limited by RAM)| Effectively infinite   | TB–PB                | Infinite (S3)   |
| Cost per GB | Expensive (RAM)       | Cheap                  | Medium               | Cheap (S3)      |
| Query model | Key lookup, simple ops| None — just files      | SQL, analytical      | SQL, analytical |
| Durability  | Optional, weaker      | 11 nines               | High                 | Inherits S3     |
| Best for    | Hot, small, fast      | Cold, big, anything    | Analytics, dashboards| Ad-hoc SQL on S3|




You move data down the ladder as it cools off (recent → cached in Redis, last month → Redshift, last year → S3 Parquet, archives → Glacier).

## API (datagetter)

| Aspect                              | Old (DataGetterDB)                             | New (ds-datagetter)                                                                              |
| ----------------------------------- | ---------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| Library                             | hand-rolled iopy/db_data_getter.py per service | `from ds_datagetter import DataGetter` (versioned, shared)                                       |
| Connection                          | dscred.DBConnect.getRedshiftConnection()       | dg.redshift — auto-resolves creds from AWS identity via Secrets Mgr (prod/DS/<user>/redshift)    |
| Subquery / params                   | sent as a string to DB                         | native "subquery" placeholder; {idselect_query} also works as a plain string parameter (substituted) |
| Feature-store table refs            | N/A (raw wkda.* tables only)                   | {{table_name}} resolved via feature-store API. Optional — wkda.* queries don't need it           |
| Temp table + main query in one string | single pd.read_sql(query, conn)              | RedshiftClient auto-splits on ';' — temp table via cursor, main query via pd.read_sql. Works for CREATE TEMP TABLE idselect ...; ... |
| S3 unload                           | custom s3_handler.py per service               | dg.redshift.unload(bucket_path) built in                                                         |
| Async / online store                | not supported                                  | dg.online.aget_record(...), dg.api.pricing.get(...) (only for inference)                         |
| Logging                             | loguru per service                             | ds_logging (structured)                                                                          |
| Local setup                         | DB env vars + dscred                           | AWS SSO + VPN (smoke-test verified)                                                              |
