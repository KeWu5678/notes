## General Spces
The traditional workflow: commit -> build -> test -> deploy(qa) -> deploy (prod). 
CI/CD optimizes this w.r.t. 
- code optimization (Ruff, plotsstyle.py)
- profiling
- real-time monitoring
- feedback loops
- caching
- load balancing
- scalability and performance testing.

## Tooling
### 1. Package Management
- npm: 
1. Create a public GitHub repository, for example `chaoruiz/my-skills`.
2. Commit and push the skill directories.
3. Users install them with:

   ```bash
   npx skills@latest add chaoruiz/my-skills
   ```

4. Publish updates by editing the skills and pushing them to GitHub.
5. Users pull updates with:

   ```bash
   npx skills@latest update
   ```

The GitHub `main` branch becomes the source of truth. You do not need `package.json` or npm publishing; add them only if the repository itself needs JavaScript tooling. New skills may require users to rerun the `add` command.

- marketplace:

The Claude Code plugin route. A git repo becomes an installable, versioned
marketplace via two manifests in `.claude-plugin/`. Skills load read-only from a
cache, so you edit in the repo, never in place.

Repo layout:

```
my-skills/
├── .claude-plugin/
│   ├── marketplace.json    # catalog: makes the repo a marketplace
│   └── plugin.json         # the plugin + its authoritative skill list
├── skills/
│   ├── writing/{caveman,zoom-out}/SKILL.md
│   └── meta/write-a-skill/SKILL.md
└── README.md
```

1. Scaffold and move skills in (each folder keeps its `SKILL.md`):

   ```bash
   mkdir -p ~/Documents/Repos/my-skills/.claude-plugin
   cd ~/Documents/Repos/my-skills && git init
   mkdir -p skills/writing skills/meta
   cp -r ~/.claude/skills/{caveman,zoom-out} skills/writing/
   cp -r ~/.claude/skills/write-a-skill skills/meta/
   ```

2. Write `.claude-plugin/marketplace.json` (the catalog):

   ```json
   {
     "name": "chaoruiz",
     "owner": { "name": "Chao Ruiz" },
     "description": "My personal Claude Code skills.",
     "plugins": [
       { "name": "chaoruiz-skills", "source": "./", "description": "My skills." }
     ]
   }
   ```

3. Write `.claude-plugin/plugin.json`. The `skills` array is authoritative —
   anything not listed does not ship (this is how deprecated folders stay out):

   ```json
   {
     "name": "chaoruiz-skills",
     "version": "0.1.0",
     "skills": [
       "./skills/writing/caveman",
       "./skills/writing/zoom-out",
       "./skills/meta/write-a-skill"
     ]
   }
   ```

4. Commit and push:

   ```bash
   git add -A && git commit -m "Initial skills bundle"
   gh repo create my-skills --private --source=. --push   # --public to share
   ```

5. Install as a plugin (in Claude Code):

   ```
   /plugin marketplace add chaoruiz/my-skills
   /plugin install chaoruiz-skills@chaoruiz
   ```

6. Remove the loose copies to avoid double-loading (same cleanup as adopting
   any external set). Leave `p-math` as a live symlink and keep anything you did
   not bundle:

   ```bash
   rm -rf ~/.claude/skills/{caveman,zoom-out,write-a-skill}
   ```

Update loop (the package-management payoff): edit a skill in the repo → bump
`version` in `plugin.json` (this is what signals an update) → commit and push →
`/plugin marketplace update chaoruiz`. Adding a new skill = add the folder, add
its path to the `skills` array, bump version; forgetting the array entry is the
usual "skill not showing up" cause.

Local-dev shortcut: `/plugin marketplace add ~/Documents/Repos/my-skills` adds
it by path and re-reads from disk, so you skip the bump/push/update cycle until
you are ready to version. Contrast with the npm/`skills.sh` route above, which
gives editable copies but manual updates; the plugin route is read-only but
versioned and auto-tracked.
